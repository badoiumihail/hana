# M0: Skeleton

Goal: a hello-world API and frontend, deployed at https://hana.ro with CI/CD and a first migration applied.

Split in two:

- **M0a (local)**: everything runs via Docker Compose on your machine; CI runs on PRs. No domain or VPS needed.
- **M0b (deploy)**: domain, VPS, Caddy, CD. Deadline: before M1 is considered done.

## Decisions

- **Repo**: public GitHub repo, trunk-based, PRs into protected `main`. `.env` gitignored from the first commit.
- **Layout**: plain pnpm workspaces: `apps/api` (NestJS), `apps/web` (SvelteKit, `ssr = false`, static adapter), `packages/api-client` (generated from the API's OpenAPI spec).
- **Contracts**: NestJS DTO classes with class-validator / class-transformer, documented via `@nestjs/swagger`.
  - `pnpm api:spec` boots the Nest app without listening, writes `openapi.json`, and exits.
  - `openapi-typescript` generates types from it into `packages/api-client`; the web app calls the API through `openapi-fetch` (types only, no generated runtime).
  - `openapi.json` and the generated types are committed, so contract changes show up in PR diffs.
- **Validation errors**: the API's `ValidationPipe` returns per-field errors in one consistent shape (e.g. `{ errors: { email: ["must be an email"] } }`) instead of Nest's default flat message array. Forms use HTML constraint attributes (`required`, `type`, `minlength`, `pattern`) for instant feedback and display the server's per-field errors; the server is the authority. No duplicated validation in TypeScript on the frontend.
- **Routing**: single origin. Caddy serves the SPA's static build at `hana.ro` and reverse-proxies `/api/*` to NestJS. Locally, the Vite dev server proxies `/api` the same way.
- **Migrations**: Drizzle migrations run by a one-shot `migrate` service in Docker Compose; `api` starts only after it completes successfully. Read every generated migration before committing it.
- **DB roles**: `hana_migrator` owns the schema, `hana_app` has DML only ([ADR 0004](../adr/0004-separate-migrator-and-app-db-roles.md)).
- **Secrets**: hand-created `.env` on the VPS (`chmod 600`); committed `.env.example` lists every variable without values. GitHub Actions secrets hold only the SSH deploy key and host fingerprint.
- **Environments**: local + production only (staging is part of the launch gate).
- **Email**: Mailpit in local Docker Compose (SMTP 1025, UI 8025). Resend arrives in M1.
- **Testing**: Vitest in both apps. `apps/api` is an ESM NestJS 12 project (the CLI's ESM option defaults to Vitest; confirm its config compiles with SWC so decorator metadata survives); `apps/web` uses Vitest via SvelteKit. Integration tests run against real Postgres (a service container in CI).

## Server hardening (do by hand, record each step in `docs/runbook.md`)

- Non-root sudo user; SSH key auth only; password and root login disabled.
- Hetzner Cloud Firewall: allow only 22, 80, 443.
- `unattended-upgrades` enabled.
- Postgres port never published in Docker Compose (Docker's port publishing bypasses `ufw`).

## CI/CD (GitHub Actions)

- **On PR**: install, lint, type-check, unit + integration tests (Postgres service container), and regenerate `openapi.json` + client types, failing if they differ from what's committed.
- **On merge to `main`**: build images → push to GHCR → SSH to VPS → `docker compose pull && docker compose up -d` (migrate runs first).

## Done when

### M0a

- [ ] `docker compose up` brings up Postgres, Mailpit, the migrate container, and the API.
- [ ] The SPA (Vite dev server) calls `/api/health` through the proxy; it returns OK, including a DB round-trip as `hana_app`.
- [ ] The first migration was applied by the migrate container as `hana_migrator`.
- [ ] `hana_app` provably cannot run DDL (e.g. `CREATE TABLE` fails).
- [ ] A PR shows CI running lint, type-check and tests against real Postgres.
- [ ] CI fails when an endpoint changes but `openapi.json` / client types weren't regenerated.

### M0b

- [ ] `https://hana.ro` serves the SPA with a valid TLS certificate.
- [ ] `https://hana.ro/api/health` returns OK in production.
- [ ] Merging to `main` deploys automatically, migrate container first.
- [ ] Postgres is unreachable from the internet.
- [ ] `docs/runbook.md` lets someone else rebuild the server from scratch.
